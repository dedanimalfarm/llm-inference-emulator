# LLM FinOps: когда окупается собственное железо?

До сих пор мы говорили о *физике* инференса — флопсах, байтах и секундах. Но в реальном мире секунды стоят денег. Главный вопрос, который встает перед любым проектом, использующим LLM: **«Использовать Managed API (по токенам), арендовать GPU почасово (Cloud) или купить собственные серверы (On-Premise)?»**

Давайте применим нашу roofline-модель и актуальные цены на API (например, с агрегатора OpenRouter) и облачные GPU, чтобы рассчитать экономику математически.

## 1. Базовые расценки (Начало 2025)

Цены на open-source модели переживают «гонку на дно». Провайдеры (Groq, Together, DeepSeek) субсидируют инференс, работая на гигантских масштабах. Типичные цены за 1 миллион токенов (среднее между prefill и decode):
*   **Класс 8B** (Llama-3.1-8B): ~**$0.05** за 1M токенов.
*   **Класс 70B** (Llama-3.1-70B): ~**$0.40** за 1M токенов.
*   **Класс 400B+** (Llama-3.1-405B): ~**$3.00** за 1M токенов.

Аренда GPU (serverless / почасовая, например RunPod, Lambda Labs):
*   **1× RTX 3090 / RTX 4090**: ~$0.40 в час.
*   **1× A100 80GB**: ~$1.50 в час.
*   **8× H100**: ~$25.00 в час.

## 2. Сценарий 1: Исследователь / Аналитик (Batch = 1)

Рассматривать маленькие модели (8B) для локального использования с точки зрения FinOps бессмысленно — API для них стоит копейки, а запускаются они даже на ноутбуке. 

Возьмем реалистичную задачу: исследователь или небольшая команда анализирует конфиденциальные документы (или использует uncensored модель) с помощью **Llama-3.1-70B**. 
Нагрузка: 50,000 токенов промптов и 10,000 токенов ответов каждый день. Итого ~1.8 миллиона токенов в месяц.

**Затраты на API:**
*   1.8M токенов × $0.40 = **$0.72 в месяц**.

**Затраты на почасовую аренду GPU:**
*   Для 70B (в квантовании INT4) нужна 1× A100 80GB или 2× RTX 3090.
*   Даже если поднимать инстанс 2× 3090 ($0.60/час в дешевых облаках) на 2 часа в день исключительно для работы скриптов: $1.20 в день = **$36 в месяц**.

**Затраты на собственное железо (On-Premise):**
*   Сборка ПК с 2× б/у RTX 3090: **$2600** (Capex).
*   Электричество на 2 часа работы в день: копейки.

**Срок окупаемости железа относительно API:** $2600 / $8.6 в год = **~300 лет**.

> **Вывод:** Для индивидуального использования с низким батчем (memory-bound) покупка видеокарты или даже почасовая аренда **не окупаются никогда**. API дешевле на порядки. Свое железо или выделенные облачные GPU здесь берут *только* ради privacy (нельзя отправлять данные в API) или отсутствия цензуры, а не для экономии.

## 3. Сценарий 2: B2B Сервис (Continuous Batching 24/7)

У вас стартап, который обрабатывает постоянный поток пользовательских запросов. Вы используете сервер vLLM, который собирает запросы в большие батчи ($b \ge 25$). В этом режиме вы переходите в compute-bound: память уже прочитана, и GPU на 100% занят перемножением матриц (FLOPs). Модель — **Llama-3.1-70B (INT4)**.

По формуле из Части 4, пропускная способность сервера с 2× RTX 3090 (TP=2) в compute-bound режиме достигает **~400 токенов/с**. При круглосуточной работе это **34.5 млн токенов в сутки**.

**Стоимость API:** 
*   34.5M × $0.40 = **$13.8 в день** ($414 в месяц).

**Стоимость аренды Cloud GPU (2× RTX 3090):**
*   $0.60/час × 24 = **$14.4 в день** ($432 в месяц).
*   *Аренда выделенных GPU при 100% нагрузке стоит примерно столько же, сколько API (иногда даже чуть дороже, если провайдер API агрессивно демпингует).*

**Стоимость On-Premise (покупка):**
*   Capex: **$2600**.
*   Opex (электричество 24/7): **$3 в день** ($90 в месяц).
*   Чистая экономия относительно API/Аренды: $13.8 - $3 = **$10.8 в день**.

**Срок окупаемости железа:** $2600 / $10.8 = **240 дней (8 месяцев)**.

> **Вывод:** При утилизации близкой к 100% покупка собственного железа окупается меньше чем за год. Если нагрузка падает (ночью трафика нет) и средняя утилизация составляет 30%, окупаемость растягивается до 2–3 лет.

## 4. Сценарий 3: Корпоративный инструмент (Только рабочие часы)

Внутренний RAG-бот компании. Трафик есть только с 9:00 до 18:00 (9 часов в день), 5 дней в неделю. Нагрузка высокая, батчи собираются, но ночью система простаивает.

Здесь **почасовая аренда (Cloud GPU)** раскрывает свой потенциал: вы можете динамически поднимать кластер (auto-scaling) только на рабочие часы.
*   Аренда 2× 3090 на 9 часов: 9 × $0.60 = **$5.4 в день**.
*   Это выгоднее, чем держать On-Premise сервер включенным (или окупать его Capex при простое 15 часов в сутки и все выходные).
*   API в этом сценарии все еще может быть дешевле, если суммарный объем токенов за эти 9 часов не превышает $\approx 13$ миллионов.

## 5. Дает ли свое железо преимущество по скорости?

Частый вопрос: *«Если я куплю свой сервер (или арендую инстанс), будет ли модель отвечать быстрее, чем по API?»*

**Ответ: Для одного запроса — нет. Для пропускной способности — да.**

1. **Скорость одного ответа (TTFT и Decode Speed).** Провайдеры API (Groq, Together) обслуживают Llama-70B на кластерах из **8× H100**, используя массивный Tensor Parallelism (TP=8). Это дает гигантскую эффективную пропускную способность памяти ($B_{\text{eff}}$) и невероятно быстрый memory-bound decode. Вы на своих 2× RTX 3090 никогда не получите скорость генерации в 100+ токенов/с для одного пользователя, которую дают гиганты.
2. **Гарантированная задержка (Predictability).** Публичное API подвержено сетевым задержкам, rate limits (лимитам запросов) и эффекту «шумных соседей» (вечером API может тормозить). Свой сервер (Cloud или On-Premise) дает 100% стабильный TTFT.
3. **Throughput per dollar.** Свое железо выигрывает не в скорости ответа одному пользователю (стриминге), а в количестве пользователей, которых можно обслуживать одновременно за те же деньги, если перейти в compute-bound (batching).

## Главное правило LLM FinOps

1. **Memory-bound (Batch ≈ 1):** Вы переплачиваете за простой (idle) мощнейшего чипа. **API всегда дешевле**. Свое железо нужно только для NDA/приватности.
2. **Compute-bound (Batch = 20+):** Вы выжимаете из кремния все FLOPs. 
    * Если нагрузка 24/7 — **покупка железа (On-Premise) выгоднее всего**.
    * Если нагрузка «рваная» или только в рабочие часы — **почасовая аренда (Cloud GPU) с автоскейлингом оптимальна**.
3. **Скорость:** Если нужна минимальная задержка (latency) для *одного* потока — API на H100 непобедимы. Если нужна стабильность, независимость от rate-лимитов и максимальный throughput — поднимайте свои инстансы.
